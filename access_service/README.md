# Аккаунты CARLEONE HELPER

Worker опубликован: https://carleone-accounts.ahienkov.workers.dev. База D1 создана,
схема применена, секреты сохранены в Cloudflare Secrets. Система использует логин
и пароль хелпера; Discord подтверждает владельца аккаунта и роль.
В `discord_access.json` включён доступ через этот сервис. Приложение не открывает
основное окно без подтверждённого аккаунта.

## Поведение

- Регистрация: собственный логин и пароль, затем подтверждение Discord и роли.
- Вход: логин и пароль; на сервере проверяется роль привязанного Discord.
- Логин: 3–32 латинских символа, первая буква, допустимы цифры, точка, `_`, `-`.
  Регистр букв не различается. Пароль: 12–128 символов, без обрезки и нормализации.
- Один Discord привязывается к одному аккаунту. Повторная регистрация не меняет пароль.
- «Забыли пароль?» восстанавливает доступ только через ранее привязанный Discord
  с ролью «Участник». Успешная смена пароля отзывает сессии остальных устройств.
- Старый аккаунт, созданный входом через Discord, при следующем запуске требует
  выбрать логин и пароль. ID аккаунта сохраняется; повторная привязка не нужна.
- Один Discord ID всегда связан с тем же аккаунтом, в том числе после переустановки.
- Условие доступа: сервер `1569352173043589263`, роль `1569352648308686888` («Участник»).
- Windows защищает ключ устройства через DPAPI. Файл `.discord-session.json` хранится
  рядом с приложением и привязан к текущему пользователю Windows, адресу сервиса и папке установки.
- Обычный выход из приложения, перезапуск и перезагрузка компьютера сохраняют вход.
- Другая версия в `version.json`, чистая переустановка или перенос папки требуют
  подтверждения Discord заново. Переустановка поверх той же папки той же версии
  неотличима от обычного запуска: для неё нужно удалить `.discord-session.json`.
- Роль проверяется при запуске и каждые 5 минут работы. Снятие роли/выход с сервера
  блокирует интерфейс и отзывает ключ устройства.
- Сетевой сбой блокирует доступ до успешной повторной проверки, но не удаляет вход.
- «Мой аккаунт» позволяет выйти на текущем устройстве.
- Аккаунты и хеши ключей сохраняются в Cloudflare D1. Ключи сессий, client secret и bot token
  в базу не записываются. Discord access/refresh tokens пользователей не сохраняются.

## Подключение Discord

1. В Discord Developer Portal создать или выбрать приложение CARLEONE HELPER.
2. Зарегистрировать точный OAuth redirect: `https://<домен-сервиса>/oauth/callback`.
3. Подключить бота этого приложения к CARLEONE HELPER для чтения данных участников.
   Права администратора и чтение сообщений не нужны; роли бот не выдаёт и не меняет.
4. В Worker задать переменные из `cloudflare/wrangler.jsonc`, а `DISCORD_CLIENT_SECRET`,
   `DISCORD_BOT_TOKEN` и случайный `AUTH_PASSWORD_PEPPER` (не менее 43 символов)
   сохранить как Secrets. Настоящие секреты не отправлять
   в чат и не включать в пакеты хелпера. Не коммитить `.env`.
5. Сервис запрашивает только OAuth scopes `identify guilds.members.read`.

Официальные API: [OAuth2](https://docs.discord.com/developers/topics/oauth2),
[участник сервера](https://docs.discord.com/developers/resources/user#get-current-user-guild-member).

## Cloudflare Workers + D1 (основное размещение)

Исходники: `cloudflare/src/index.js`, миграции: `cloudflare/migrations/*.sql`.
Приложение Discord: `1570581256754827326`. Redirect:
`https://carleone-accounts.ahienkov.workers.dev/oauth/callback`.

Из `access_service/cloudflare`:

```sh
npm ci
npm test
npm run build
npx wrangler login
npm run db:remote
npx wrangler secret put DISCORD_CLIENT_SECRET
npx wrangler secret put DISCORD_BOT_TOKEN
npx wrangler secret put AUTH_PASSWORD_PEPPER
npm run deploy
```

Команды `secret put` запрашивают значения интерактивно. Не передавать ключи аргументами
команд и не хранить их в исходниках. Для локального запуска скопировать
`.dev.vars.example` в `.dev.vars`, заполнить, затем `npm run db:local` и `npm run dev`.

Удалённая схема и миграция 0002 применены через SQL-консоль dashboard. Миграции содержат
`IF NOT EXISTS`, поэтому повторное применение через Wrangler безопасно и зарегистрирует
её в журнале миграций. Существующие аккаунты и сессии не удаляются.
База привязана как `DB`; идентификаторы размещения находятся в `wrangler.jsonc`.

Пароль передаётся только по HTTPS и не сохраняется на устройстве. В D1 хранятся
индивидуальная случайная соль и HMAC от PBKDF2-SHA256 (100000 итераций — ограничение
WebCrypto workerd). Pepper хранится отдельно в Secrets; не удалять и не менять его
при обычном обновлении: это сделает прежние пароли недействительными до восстановления.
Секреты и пароли не логируются. Попытки ограничены по IP и логину.

API: `POST /v2/register`, `/v2/login`, `/v2/recover`, `/v2/account/setup`,
`/v2/registration/{id}`. Старый `/v1/login` отключён; `/v1/session/check` и logout
сохранены. Учётная запись без логина получает `setup_required`, а не доступ к хелперу.

OAuth state, незавершённые входы и ограничения частоты также находятся в D1.
Перезапуск Worker сохраняет их. Cron `17 * * * *` очищает только просроченные
попытки входа и счётчики частоты; постоянные сессии по времени не удаляются.
Запросы авторизации читают основную реплику D1. Invocation logs отключены,
чтобы одноразовые коды из callback URL не попадали в журнал запросов.

После успешного `/health` и живого входа включить `discord_access.json` и задать
`service_url`. До этого ограничение доступа остаётся выключенным.
Miniflare-тесты используют настоящий runtime Worker и локальную D1; внешнее API
Discord подставлено. Они проверяют однократный OAuth, параллельные запросы,
постоянные сессии, отзыв роли, сетевые сбои и ограничения частоты.

## Python-прототип (не используется в Cloudflare)

Нужен постоянно работающий HTTPS-сервис и постоянный диск для SQLite. Из корня
проекта установить `access_service/requirements.txt`, затем запустить:

```sh
gunicorn --workers 1 --threads 8 --bind 127.0.0.1:8080 access_service.wsgi:application
```

Один worker обязателен: незавершённые OAuth-входы хранятся в памяти процесса.
Несколько потоков поддерживаются. Перезапуск сервиса не сбрасывает уже созданные
аккаунты и сессии, но незавершённый вход придётся начать заново.

Перед сервисом настроить HTTPS reverse proxy. База `ACCESS_DB_PATH` должна находиться
на постоянном диске с ограниченным доступом; нужны резервные копии. Для OAuth callback
не записывать query string в access logs: он содержит одноразовый код подтверждения.
Секреты задаются через окружение сервиса, а не через клиентский конфиг.

После проверки `/health`, успешного входа участника и отказа аккаунту без роли:
в `discord_access.json` указать `service_url` и включить `enabled`. Этот публичный
конфиг попадёт в Windows-пакет. Серверная папка, SQLite, `.env` и ключи пользователей
в клиентский пакет не включаются.

## Проверка

```sh
.venv/Scripts/python.exe -m unittest test_discord_access test_bootstrap test_software_update test_app_refresh
```

Без реального Discord-приложения тестируется подставной API. Это проверяет сохранение
аккаунта и сессии, привязку к версии/установке, отзыв доступа, одноразовый OAuth state,
защиту polling, сетевые ошибки и реальный Windows DPAPI, но не заменяет живой вход
через настроенное Discord-приложение.
